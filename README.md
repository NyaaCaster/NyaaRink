# NyaaRink

[English](README-EN.md)

便捷式远程 SSH 控制协助服务。

Portable remote SSH control assistance service.

通过一次性邀请网页，让受邀用户明确授权远程 SSH 协助。支持 CLI、REST API 和 MCP，既可手动操作，也可接入 AI Agent。

## 一、S端用户：部署与使用

**S端（邀请机）**部署 NyaaRink 并发起协助；**C端（受邀机）**接受邀请、运行连接程序，开放自己的 SSH 访问权限。

### 部署准备

- 使用 Docker Compose 部署，默认对外提供 **HTTPS/WSS 5116**；C端通过出站连接接入，无需映射 C端 SSH 端口。
- 准备可访问的域名和自行申请的 **Let's Encrypt 证书**，按 [`.env.example`](.env.example) 配置公开地址、管理 API Key、证书与数据目录。
- 准备服务镜像和匹配的已签名客户端发行包。当前需自行构建发布，详细步骤见[部署标准](.docs/技术标准-部署与验收.md)，维护和备份见[运维手册](.docs/运维手册.md)。

`.env`、证书私钥、会话密钥及授权数据均应私密保存，不上传到 Git 仓库或打入镜像。备份不能只保存业务数据库，还需保护独立授权账本、密钥库和主密钥。

### 使用流程

1. S端通过 CLI、API 或 MCP 创建邀请，将链接交给 C端用户。
2. C端查看权限说明，点击“接受访问”，下载连接包并按说明运行。**仅打开网页不会授予权限。**
3. C端上线后，S端可执行命令、使用交互终端或传输文件；网页显示连接状态、时长及流量等信息。
4. 协助结束后，由 C端点击“断开连接”，或 S端调用断开命令撤销授权，并确认清理状态。C端随后删除下载包和解压副本。

MCP 入口为 `https://<你的域名>:5116/mcp`，使用 `Authorization: Bearer <MCP_API_KEY>` 鉴权，也支持 stdio 接入。CLI 命令、接入示例和操作说明见[使用指南](.docs/使用指南.md)。

### 使用注意事项

- **邀请在 C端成功接受时消费。**未接受的邀请可取消；已接受但尚未连接的授权，需要通过“断开连接”撤销。
- **断网、关闭网页、退出程序或重启均不撤权。**程序支持用户登录后自动恢复，只有双方主动发起断开才永久撤权；C端离线时，本地清理可能需要等待其重新上线。
- 默认授权普通账户，SSH 能力由该账户的系统权限决定。需要管理员或 root 权限时，应事先与 C端用户沟通确认。C端页面会告知协助者可能使用 AI Agent。
- 默认不持久记录命令正文、输出或传输文件。文件传输接口限制在账户主目录内，这不构成对 SSH 命令的沙箱限制。
- 恢复旧业务数据库不会恢复已撤销权限；独立授权数据缺失或完整性不明时，服务冻结访问。

### C端支持范围

| 系统 | 连接方式 |
| --- | --- |
| Windows 11 / Server 2022+ x64 | 解压 ZIP，进入包内文件夹运行 `start.bat`；无需预装 Node.js 或 .NET。使用随包分发的微软 OpenSSH 组件，独立监听回环地址，不修改系统 SSH。 |
| Ubuntu 22.04 / 24.04、Debian 12 / 13 x64 | 使用原生客户端与系统 OpenSSH；缺少服务时按提示确认准备，不自动升级已有 SSH。 |

Windows 随包组件固定为微软 **OpenSSH 10.4.0.0p1-Preview**，官方标记为非生产就绪，部署者应了解这一边界并跟踪更新。上述为 V1 目标范围，实际验证及保留未测项见[验收记录](.docs/验收记录.md)。

## 二、二次开发者：工程与注意事项

服务端与 CLI 使用 TypeScript / Node.js 24，网页使用 React，C端连接程序使用 Go；通过 nginx 提供统一 HTTPS/WSS 入口。

安装依赖并进行基础检查：

```sh
npm ci
npm run typecheck
npm run lint
npm test
npm run build
```

主要代码位于 `apps/` 与 `packages/`。客户端发行由 `scripts/client-release.py` 构建，服务镜像由 `rebuild.py` 构建发布；构建发布与容器启动是独立步骤。

二次开发请保留以下约束：

- 邀请消费、主动撤权、断网保留授权和恢复冻结规则属于核心行为，修改前先阅读[设计决策](.docs/设计决策.md)与[开发计划 SSOT](.docs/开发计划-SSOT.md)。
- 客户端发行必须验签。独立发行者应生成自己的签名密钥，同步替换服务端与客户端的发行验签公钥，不能通过关闭验签完成部署；当前 Windows 发行构建还需校验微软组件签名。
- 私密配置、发行签名私钥、授权数据及客户端发行产物不纳入源码仓库；修改数据库前备份，测试后清理临时数据。
- 面向使用者 AI Agent 的操作约定见[产品使用技能](.agents/skills/nyaarink-assist/SKILL.md)；接口约定见[API、MCP 与 CLI 标准](.docs/技术标准-API-MCP与CLI.md)。
