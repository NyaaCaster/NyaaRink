# 技术标准：C端部署、自动恢复与撤销

2026-10-22，已批准设计基线1，对应R02、R03、R05。用户已确认登录后自动恢复，不要求系统无人登录时在线。

## 1. 支持矩阵与交付形态

V1推荐验收范围：Windows11/Windows Server2022及更新的受支持版本x64，Ubuntu22.04/24.04、Debian12/13 x64，OpenSSH8.9+。Windows普通本地账户、Linux普通账户为必测；Windows域账户、受限企业策略和其他sshd实现不承诺未经测试兼容。管理员/root另做明确授权路径。

TypeScript编译并打包为JS，附固定Node24官方便携运行时；C程序不依赖better-sqlite3等原生扩展。下载包按OS/arch分开，S镜像携带发布后的包，只从本实例HTTPS提供。不要求C安装npm或从外部动态拉“最新”代码，不采用不稳定SEA注入作为V1交付基础。

Windows `.bat`、Linux `.sh`是会话引导入口：固定可信来源、sessionId、短时引导Key、发行版本和清单摘要，输出授权说明后运行校验过的连接程序。用户可先查看内容。安装包及临时下载不放Git；发行清单、构建脚本和源码入Git。C包携带Node及依赖许可证。

发行清单包含文件名、OS/arch、版本、SHA256、最小系统版本；清单使用离线Ed25519发行私钥签名，校验公钥为公开代码常量，可以入库，实际SSH公钥与证书文件不能入库。下载脚本和校验程序不能从同一未验证来源临时替换信任根。发行私钥位于私密目录，不进入镜像或C脚本；制作包仅输出签名。Node原包的官方校验在研发打包阶段完成。

HTTPS及随脚本提供的校验防传输篡改，但同一S源被控制后仍可修改新脚本；不宣称能防恶意S端。TLS链错误、哈希失败、签名错误、发行版本回退均停止安装，保留授权为等待/冻结状态，不静默跳过校验。

## 2. SSH服务准备

2026-10-22用户明确确认：Windows连接入口内置UAC请求，仅固定的系统安装/启动及只读sshd配置检查使用管理员权限。连接程序、设备状态、公钥与登录任务仍归最初运行脚本的用户；UAC中输入其他管理员的凭据不改变SSH目标账户。检查使用原用户与回环连接的Match上下文，只返回配置文本，不返回主机私钥；不放宽私钥ACL，不执行下载的程序为管理员。UAC拒绝或检查失败保留等待状态。

同一会话连接脚本检测并复用已有SSH服务；缺少时经本地单独确认和必要提权，安装Windows OpenSSH Server或Debian/Ubuntu openssh-server并启动，已有服务未运行时经确认启动。完整顺序以SSOT的“P3连接脚本工作流程”为准。网页保持“下载连接脚本”按钮，用简短说明交代按需安装启动，不另列手动安装命令区。标明安装可能需要管理员/root及系统原生组件可能保留，不能把安装服务的提权等同于远程账户提权。

自动安装步骤必须本地显示将做的变更并单独确认，不采集或上传账户密码。不默认新增公网/局域网入站规则，不自动关闭现有防火墙，不覆盖已有sshd_config，不停止其他会话的sshd。若系统安装器自行创建入站规则，必须提示实际变化，交由C确认处理，不能声称安装完全无网络影响。

使用已安装sshd的本地回环入口；端口由C本地确认，默认22，绑定后S不可修改。检查pubkey认证可用、服务归属与主机公钥。已有服务可能本来监听外网，本服务仅追加本次公钥，不自动改全局监听；页面解释其区别。

如果sshd未配置开机启动，可在安装确认步骤启用其系统服务自启动；其作用是维持系统SSH服务，不改变实际授权账户。项目退出/撤销不卸载系统sshd，也不删除原有授权项。

## 3. 账户与授权文件

- 默认当前普通账户；检测root、管理员组成员、提升token时明确警示并再次确认，建议改用普通账户。不能仅检查shell是否“以管理员运行”来判定目标SSH权限。
- 普通用户只追加自己的authorized_keys；Unix目录0700、文件0600。行带唯一会话标识，优先 `from="127.0.0.1,::1",restrict,pty`，允许shell/PTY与SFTP，禁止agent/X11/端口转发。安装时验证本机OpenSSH支持这些选项，失败则报告不支持，不静默移除限制。
- Windows普通账户使用其profile的`.ssh/authorized_keys`及正确ACL；管理员账户可能受Match Group规则影响使用ProgramData下的administrators_authorized_keys，必须读取有效sshd配置并使用对应权限规则，不能写错文件后宣称授权成功。
- 所有文件变更先读取与备份，原子写回，保留现有行与ACL；卸载按本次session唯一标识及完整公钥匹配删除，不能删除整个authorized_keys或其他会话的行。
- 登记主机公钥须从可信本地配置/公钥文件取得，并与回环握手核对。S设置hostVerifier或严格known_hosts，不采用ssh2默认auto-accept。密钥轮换需C本地确认并签名更新绑定，网络错误不会自动信任新主机。
- 私钥仅在S，限制来源为回环能减少C原有外网sshd暴露，但同账户或root被攻陷仍可修改授权，超出服务保证。

## 4. 登录后自动恢复

Windows：当前确认账户的“用户登录”计划任务，运行最低权限、无需存储用户密码，`Run only when user is logged on`，使用固定绝对程序路径及sessionId。启动器不含引导Key，不依赖下载脚本，读取私有持久设备状态。安装由该账户确认；若用户为了安装sshd提升过权限，必须返回目标账户上下文创建任务。

Linux：`~/.config/systemd/user/nyaarink-<session>.service`，WantedBy=default.target，Restart=on-failure，禁止自动启用linger，不要求root。用户登录启动其user manager后恢复，注销后是否退出由系统user manager策略决定；无论进程在线与否，授权都不自动撤销。缺少systemd用户管理器时提示不支持，不临时改用cron。

首次安装即启动连接程序；默认有清晰本地状态/停止说明。单设备状态锁避免重复启动。跨启动状态保存设备私钥、实例ID/epoch、会话ID、SSH公钥标记、主机绑定与撤销标记。Windows目录位于当前用户LOCALAPPDATA，Linux遵循XDG_DATA_HOME，0700/最小ACL，不写公共临时目录。

暂时停止进程只暂停在线状态，登录/手动运行后恢复。移除下载bat/sh不卸载程序，也不撤销；双向断开后提示删除下载脚本。系统任务/服务名称带sessionId，允许多会话共享运行时但独立凭据和授权行。

## 5. 本地用户命令

程序提供 `status`、`resume`、`resume-browser <code>`、`disconnect`、`cleanup`；操作对象均需明确sessionId，多个会话不能默认全部结束。

`disconnect`是明确主动撤销：打印影响并本地确认，先持久化本地revoked，终止流、删除本次授权行与登录项；联网时提交S，离线时保留最小补交凭据，下一次登录仅执行补交和清理，绝不重新提供SSH。`cleanup`仅重试已撤销项清理，不能将有效会话当垃圾删除。

若用户直接删除程序/设备状态，S可能仍显示有效但离线，不能凭此伪称撤销；页面与文档应建议先disconnect再删除。设备丢失时可由S显式撤销旧会话后重新邀请。

## 6. C网页标准

单一邀请/授权状态页，以中文为默认，提供英文关键说明。移动窄屏可读，键盘操作与状态文本完整，不只用颜色传达状态。V1没有管理后台或浏览器终端。

接受前：协助者自报名称（不能暗示已实名认证）、协助目的、账户待本机确认、默认权限、AI告知、网络断开仍保留授权、登录后自动恢复、日志范围、停止方法、源码入口。一个明确的“接受访问”动作，先阅读再点击。

接受后：下载与校验说明、sshd步骤、实际账户与主机绑定状态、授权时长、在线累计、SSH连接数、字节流量、受控操作数、RTT及采样时间；明确“访问已授权”和“设备在线”两项状态，页面离线不推断授权已结束。

断开为独立显著按钮，说明将终止当前操作并撤销本次权限，二次确认防误触；提交后显示真实持久化结果及两端清理进度。断开成功提示删除本次下载脚本；刷新无有效会话内容。不把网络超时伪装成断开成功。
