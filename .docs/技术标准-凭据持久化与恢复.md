# 技术标准：凭据、持久化与恢复

2026-10-22，已批准设计基线1，对应R05、R06、R08。数据库恢复保留有效授权、权威不明则冻结的业务规则已批准。

## 1. 权威分层

业务SQLite不能决定一份已经撤销的授权重新有效。采用三个独立持久化对象：

| 对象 | 内容 | 恢复规则 |
| --- | --- | --- |
| 业务目录 STATE_DIR | SQLite WAL、索引、任务元数据、指标投影 | 可从旧备份恢复，随后从最新权威账本重放 |
| 权威目录 AUTHORITY_DIR | 实例ID/epoch、追加事件账本、trusted head、每会话加密密钥包、持久nonce/幂等登记信息 | 不随数据库恢复而回退；整目录独立保全 |
| 主密钥 SESSION_MASTER_KEY_FILE | 32字节随机加密主密钥 | 单独权限管理、与权威数据分别备份；丢失时不能解密，不生成替代密钥冒充原实例 |

普通重启、容器更新使用相同三者，不改变epoch、不使授权过期。DB恢复不删除有效授权、不轮换epoch、不自动调用revoke。

## 2. 事件提交和崩溃一致性

单实例、单写者，启动获取独占文件锁。每条事件包含seq、instanceId、epoch、schemaVersion、eventId、时间、前事件hash、payload和HMAC。事件payload包含恢复授权投影所需元数据，秘密放加密密钥包；HTTP重试所需幂等ID纳入同一事件。追加采用长度前缀+校验，写后fsync。

先把新密钥包写临时文件、fsync并原子重命名，再提交引用它的账本事件；最后更新SQLite投影与trusted head。任意临时残留只能形成无授权引用的孤立文件，不可自动授予访问。

启动按账本重建内存权威状态，再校准DB：已fsync事件而head未更新，可验证尾部后推进head；head已引用却缺事件、链损坏、文件锁冲突、不同实例/世代、DB声称比权威更晚，均进入frozen。只允许忽略无完整校验的末尾未提交帧，不能跳过中间损坏。

接受邀请、登记设备、撤销、替换引导Key、浏览器重新绑定均为权威事件；DB更新失败不能导致这些操作被重做。任务输出不进入账本。

撤销先提交，后删密钥包：若删除前崩溃，启动依revoked重试清理；不能因密钥仍在盘上恢复访问。磁盘故障导致撤销提交未成功，立即中断访问并标冻结，响应必须说明“未持久化确认”，客户端继续幂等重试。

## 3. 加密与文件权限

- 使用Node crypto AES-256-GCM，每对象独立随机nonce和认证tag，AAD含instanceId/epoch/sessionId/secretType/schemaVersion。不得重复nonce，不自创密码算法。
- 主密钥不在.env中直接粘贴，.env仅指向私密文件；管理API Key仍按用户要求由.env注入。禁止默认管理Key、空Key或匿名管理模式。
- 会话SSH私钥、浏览器敏感恢复材料及需要恢复的凭据加密；高熵APIKey/引导Key/Cookie只保存摘要用于比较，恒定时间校验。随机凭据至少256位。
- Linux目录0700、秘密文件0600，容器非root专用UID；Windows C端目录仅实际账户、SYSTEM及本地管理员可访问，拒绝Everyone/Users宽权限继承。
- 原生SSH配置及解密私钥物化到S服务的tmpfs私有目录，权限0700/0600，原生配置固定IdentitiesOnly、StrictHostKeyChecking和私有known_hosts。重启后从有效密钥包重建；临时缓存消失不等于授权撤销。
- 不承诺JavaScript内存绝对清零、不承诺SSD/快照/历史备份物理擦除。撤销的安全依据为权威拒绝访问、切断连接和清理活跃秘密；旧加密备份必须隔离，不能覆盖最新撤销记录。
- 主密钥丢失、密钥包缺失不会自动revoke，标记frozen并报告恢复所需对象。管理Key轮换不删除C授权；支持现Key与previous Key短期并行，窗口最长24小时并明确告知旧Key有效截止。

## 4. 支持的备份与恢复操作

运行中的SQLite用backup API创建一致备份，不直接复制有WAL的主文件。任何数据库修改或迁移前也必须先备份。备份manifest写schema、实例ID、epoch、账本seq和各文件hash，不含秘密正文。备份目录、权限与构建上下文隔离。

V1提供Python运维入口，具体命令契约：

- `backup.py --database`：创建业务DB一致备份，记录当时权威head，不回退或替换权威目录。
- `backup.py --authority`：暂停授权写入片刻，导出权威账本/密钥包一致副本；主密钥单独备份。备份是恢复资源，不天然成为最新权威。
- `restore.py --database <backup>`：停止业务访问但不revoke，备份当前DB，验证instanceId/epoch，加载最新权威目录，全量重建授权投影，再恢复连接。备份晚于当前权威head时冻结，不用备份猜测有效状态。
- `restore.py --verify-authority <directory>`：只验证链、head、实例和密钥包引用，默认不写、不启服务。

官方DB恢复必须重放**所有当前权威事件**：旧DB中已撤销的会话保持撤销；旧DB尚无的新有效会话也能重建；旧脚本/票据不复活；待清理任务继续执行。恢复时暂停访问属于不可用，不是授权销毁。

若整机丢失最新权威目录，只找得到早期全量备份，V1不能证明备份之后是否发生撤销，禁止直接开放访问。管理员需提供独立保存的最新权威副本并核验，或与C重新协商新的授权；系统不得静默“全撤销”替用户决策。

同盘HMAC和hash链防篡改检测不等于防整盘回滚。恶意root可同时回滚主密钥、账本和head；不在V1威胁模型。需要防整机历史回滚和自动灾难恢复时，应在后续版本引入外部不可回退见证/权威存储，不能靠DB内tombstone宣称已经解决。

## 5. 保留、清理和访问日志

- 非撤销授权与必要秘密：保留至主动断开，不做TTL清理；停止计划任务也不触发TTL。
- 撤销事件最小摘要、seq、设备验证公钥、cleanup状态：随实例保留，以支持拒绝重连和清理回执；不再保留可访问凭据。账本不自动截断，不把30天审计保留期套用于撤销权威。
- 业务审计元数据默认30天，仅actor类别、sessionId、操作类别、时间、耗时、退出状态、错误码、流量；默认不存命令、参数内容、终端输出、文件内容或下载脚本。任务结果仅内存保留最多10分钟/任务1MiB，用后可立即丢弃。
- IP用于速率限制，默认仅内存保留；不作为永久用户画像。系统nginx/sshd可能另有日志，部署说明要列出并提供调整方法。
- nginx禁止记录完整邀请码、token、请求体、Authorization/Cookie和脚本响应；应用日志对路径中的邀请/会话识别符做脱敏。静态公开资源可正常缓存，敏感接口一律no-store。
- 外部备份中旧秘密不能声称已物理销毁；运维文档规定加密、访问控制与到期删除。公开仓库不包含任何备份。
