# 授权权威实现说明

2026-10-22，P2。本文解释已批准基线的工程实现，不替代开发计划SSOT。

`authority.ts`管理独立身份、长度帧追加账本、HMAC/hash链、trusted head和单写者锁。事件fsync成功是提交点；head落后可在验证完整尾部后推进，head超前、链损坏、错误主密钥和锁冲突冻结。只允许舍弃末尾不完整且不被head引用的帧。Linux持久化重命名同时fsync目录；Windows没有相同目录fsync接口，本地测试不代表Linux断电持久性验收。

`service.ts`在单个异步队列中执行所有业务变更。消费邀请与接受、浏览器绑定合成一条事件。浏览器Cookie摘要、登记ID、设备公钥及必要元数据进入账本；原始邀请码与引导Key只在加密的幂等响应包中保存，并随消费、替换、登记或撤销清理。账本和SQLite不存这些明文；会话SSH私钥仅在S密钥库中，登记响应只返回公钥。

设备登记对规范化登记数据、实例、epoch、session和引导Key摘要签名。同一登记数据与设备签名可重取登记结果；持旧脚本换设备或改账户遭拒。登记后设备操作使用30秒单次nonce和操作绑定签名，浏览器恢复不能更换设备。撤销公钥仍保留，以接收离线设备的签名清理回执。

`projection.ts`中的SQLite只是投影。每次写入前执行一致backup API并保存manifest；账本提交后投影写入失败冻结，重启从账本重建，不重新消费邀请。幂等且不改变状态的请求不重复写DB。备份留在私密目录，当前不自动删除历史备份；容量监控和保留运维在P8交付。

`backup.py --database`用Python SQLite在线backup API保存一致快照和摘要manifest。`backup.py --authority`须先暂停服务，取得同一writer锁后复制账本和加密库；不复制主密钥。恢复入口`restore.py --database <文件>`同样要求服务停止，不自动停止任何服务。它校验备份manifest、实例及进度，再备份当前DB并从最新权威重建；不复制旧权限覆盖最新账本。普通重启使用同一权威与主密钥。`restore.py --verify-authority <目录>`只读核验，不创建替代实例或更改head，运行中并发变更时应暂停后再复核。

运维入口需要同目录私密.env；Node运维模块需要构建产物和依赖。容器部署时的宿主包装调用、备份目录保留策略和健康上线仍由P8实现，不把P2视为已上线产品。当前ready仍返回503，避免无隧道时开放生产入口。

HTTP边界实行准确Host/Origin、Bearer恒时比较、HttpOnly/Secure/SameSite Cookie和CSRF，32KiB JSON上限，敏感响应no-store/no-referrer。P2新增浏览器context和邀请读取API供P6使用。限流当前以应用直接连接来源为键，不信任任意X-Forwarded-For；P8结合唯一内部nginx来源核验后再识别C来源，不能直接打开全局trust proxy。
