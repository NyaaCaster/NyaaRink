## R. 已整体批准的实现基线

2026-10-22 用户明确回复“批准 R01–R08 及其引用标准”。以下全部成为冻结的开发基线；批准设计不代表已经开始实现、通过验证或授权提交推送。

| ID | 推荐决定 | 成本、限制与替代 |
| --- | --- | --- |
| R01 | 单实例 npm workspaces；Node24 Debian slim、Express5、SQLite/better-sqlite3；React19/Vite8/Tailwind4/TS7；MCP SDK1.x、Zod4、ssh2、ws | 保留指南的工程风格，更新已过时版本；镜像大小不承诺旧指南 40MB。版本组合 P1 构建验证；不引入 Go/Rust 或分布式服务 |
| R02 | V1 C端认证矩阵：Windows11/Server2022+ x64；Ubuntu22.04/24.04、Debian12/13 x64；OpenSSH采用平台支持矩阵与能力验收，取消8.9统一硬门槛；Linux 需 systemd 用户管理器 | 不覆盖 Windows10、32位、ARM、musl、WSL及 macOS；扩展系统进入后续版本，不伪称所有 sshd 系统都已兼容 |
| R03 | C端 TS打包 JS + 固定 Node便携运行时，bat/sh负责引导；Windows当前用户登录任务、Linux systemd user服务 | 无需预装 Node，不采用 SEA/废弃 pkg；程序及运行时有下载体积。默认登录即恢复，脚本退出不撤权；卸载必须显式确认本次断开 |
| R04 | 一控制 WSS + 每条 SSH 一数据 WSS；只桥接本机登记回环 sshd，严格主机公钥固定，不自研多路复用 | 多个 TCP/TLS 连接，但故障隔离、背压和实现更简单；默认最多20个授权会话、每会话4个SSH流 |
| R05 | 浏览器 Cookie+CSRF、设备 Ed25519签名、短时一次性引导 Key、管理 Bearer Key分权；原浏览器可补发未兑换引导脚本，本机设备可恢复浏览器身份 | 丢失设备私钥不能靠旧下载脚本复活；需主动结束旧会话后重新邀请；管理 Key属于单管理员完整信任 |
| R06 | 独立追加授权账本+加密密钥库是授权权威，SQLite是投影；恢复 DB 必须重放最新账本；损坏或缺失冻结，禁止回退账本 | 运维需额外保护整个权威目录和主密钥；不保证最新权威数据全部丢失后的整机自动恢复，也不承诺防恶意 root回滚全部磁盘 |
| R07 | REST与MCP共享业务层；无状态 StreamableHTTP + 本地 stdio桥；异步执行任务、CLI交互WSS、流式 SFTP；私钥及原生 SSH配置只在 S侧 | V1无旧 SSE/OAuth/团队RBAC/浏览器终端；原生SSH可执行目标账户所有可执行行为，API目录限制不是 OS沙箱 |
| R08 | Docker nginx TLS入口 + Node服务；宿主 acme.sh续期，目录只读挂载；具体配额、指标、默认过期和数据保留依技术标准固定 | 未兑换邀请24小时过期、引导10分钟；已授权无自动过期。默认不留命令正文，审计元数据30天；撤销摘要随实例保留 |

各项细节分别落在生命周期、客户端、安全、接口和部署规范中；对 R01–R08 的批准包含这些文档中的推荐参数。纯编码细节可按规范实施；改变授权语义、权限边界、支持矩阵、协议版本或数据恢复边界必须走设计变更，不得临时拍板。

## 明确不采用

- 仅访问网页就修改系统、在浏览器内藏管理 Key、未接受即消费邀请。
- 用连接存活时间代表授权有效期、以 SSH exit 作为撤销、从 C离线推断用户已断开。
- 另开公网 SSH 中继端口、暴露任意内网目标代理、关闭 TLS/SSH主机核验。
- 通过回退业务数据库覆盖最新撤销记录，或恢复时静默销毁全部有效授权。
- 分发私钥给远端 Agent、默认保存终端正文、以流量包数量表示命令次数。
- 改写已推送历史、停止现有5115服务或直接部署未实现产品。提交推送及按阶段部署已获后续连续实施授权。
