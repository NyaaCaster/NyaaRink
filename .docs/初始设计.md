## 目标与术语

邀请机简称 S端，是服务宿主机。受邀机简称 C端，是用户主动开放本机 SSH 访问权限的 Windows/Linux 电脑。协助者 CLI/Agent 可能运行于 S端，也可能运行于另一台电脑，设计时不得混淆二者的文件系统。

S端通过经鉴权的 API/MCP 生成随机后缀邀请网址。C端用户打开网页、明确接受授权并运行本地连接脚本/程序后，S端可以经 SSH 协助操作该账户。普通网页本身不负责修改本机 SSH 授权或独立建立本地 SSH 隧道。

## 已确认的不可变业务约束

1. 邀请只在 C端点击“接受访问”、服务端接受成功时原子消费。GET、预览、刷新不消费。并发接受只能有一方成功。
2. 接受后，其他人访问原邀请地址不能获得有效邀请信息。原浏览器凭独立会话继续显示页面，连接中刷新可恢复。
3. SSH 授权仅因 C端或 S端主动发起“断开连接”而撤销。网络超时、断网、浏览器关闭、连接程序意外退出、S端容器重启都不能自动销毁授权。
4. 意外断线后保留重连能力。C端连接程序恢复出站通道后，S端可重新连接。保留私钥不等于断网时仍可访问。
5. C端 GUI 和 S端 API/CLI/MCP 都提供明确的主动断开入口。主动断开撤销本次凭据、终止现有通道并清理本次配置；结束后旧脚本不得恢复会话。
6. 断开后当前网页显示结束状态和删除下载脚本的提示；刷新后不再返回有效会话内容。
7. 全部公网业务统一通过 HTTPS/WSS `5116`，包括网页、API、MCP 和隧道。不另开公网 SSH 中继端口。2026-10-22 用户确认替代原5115要求，避免占用macmini现有服务。
8. HTTPS 采用自行申请、管理和续期的 Let's Encrypt 证书，使用 DNS-01；不是自签名证书。域名和凭据不硬编码。
9. 默认普通用户 SSH 权限。高权限需求由 S端持有者与 C端用户自行沟通，由 C端明确以管理员/root 运行并确认实际授权账户。安装 sshd 提权不能隐式变成高权限远程授权。
10. C端必须告知“S端可能使用 AI Agent 参与操作”；服务无法可靠判定 CLI 操作来自人还是 Agent。
11. Agent 接入使用 S端 `.env` 配置的 API Key；缺少 Key 时拒绝启动管理服务。长期管理 Key 不随单次会话销毁。
12. 真实配置、证书文件、所有私钥、ACME/DNS 凭据、SSH 凭据及会话数据不进入 Git、构建上下文、镜像或日志。

## C端体验

网页展示协助者身份、用途、目标账户、权限、AI 参与可能性、授权规则、日志范围及撤销方法。保留“下载连接脚本”入口，由同一连接程序经确认按需安装/启动 sshd，不另设手动安装说明区。Windows 按后续批准的 A19 下载 ZIP，解压运行可读 start.bat；Linux 下载 .sh，不改为 PS1。

会话专用脚本在接受成功后下载，包含本次独立引导 Key，不包含 S端管理 API Key。引导 Key 为短时一次性凭据，换取可持续重连的设备会话凭据；引导 Key 过期不得撤销已存在的授权。未登记设备前由原浏览器替换引导凭据，旧凭据立即失效；已登记设备不得借此换绑，按已批准生命周期标准执行。

网页至少展示：接受访问、断开连接、等待本机连接/在线/离线/重连中/已结束状态、授权时长、连接时长、上下行字节数、SSH 连接数、S端到 C端连接程序的往返延迟。操作次数只统计经受控 API/MCP 发起的操作，不能将发包数量称为命令次数。

示例告知文案：

> S端可能由人工操作，也可能使用 AI Agent 经 SSH 执行操作。本服务无法可靠识别每条操作的实际发起来源。访问权限以你确认的账户及其系统权限为准；网络中断不会撤销授权，需主动点击“断开连接”结束授权。

## 生命周期与撤销语义

授权状态独立于连接状态。建议授权状态为“已授权、撤销处理中、已撤销”；连接状态为“等待连接、在线、离线、重连中”。具体字段按已批准生命周期标准执行。

主动断开应先持久化不可逆撤销状态，拒绝新连接，再关闭现有隧道和 SSH 会话，销毁 S端会话密钥及配置，并通知 C端清理本次授权与临时文件。保留不含秘密的撤销记录，防止恢复旧备份或延迟重连导致复活。

S端主动断开时如 C端离线，S端立即撤销；C端清理只能在恢复联系或执行本地清理后完成。网页应区分“访问已撤销”和“两端清理均已确认”。网页无法向 S端提交撤销时不得显示成功；本地程序应提供紧急撤销入口，并在恢复网络后补交撤销。

关闭浏览器不撤销授权。主动结束后，刷新不能恢复有效信息。下载文件删除属于友好提示，真正安全边界是凭据已经失效。

SSH 断开不能回滚已执行修改、收回已读取数据，也不能保证终止由高权限账户另行创建的后台任务。清理只移除本服务新增项，不破坏原有 SSH 配置、公钥和服务。

## S端操作入口

提供 REST API、通用 MCP、CLI 接入说明，参考 NyaaQiny-MCP 的工具注册和 Bearer 鉴权组织方式。计划接入 Codex、Claude Code、OpenCode、zcode；兼容性须逐个验证，不因声称支持 MCP 就标记通过。

拟定能力：创建邀请、查询会话、查询指标、SSH 执行、获取受限连接信息、主动断开。名称和协议以已批准API/MCP/CLI标准为准。远端 MCP 默认不向模型返回私钥。

Agent 工具说明必须明确：网络断线不等于授权结束；完成协助后显式调用断开工具并检查结果；退出 SSH、关闭终端或停止调用工具均不会撤销权限。

## Docker 与 LE 部署

统一 Docker Compose 部署。证书由宿主机管理，以只读目录挂载并支持安全 reload；不得烘焙入镜像。ACME/DNS 凭据留在宿主机私密位置。参考现有 LE 文档的机制，但不得复制其真实域名、IP、部署路径和账户配置到开源文件。

会话授权需跨容器重启保留，因此凭据不能只存 tmpfs。持久化加密、主密钥管理、独立账本与恢复冻结规则按已批准持久化标准执行。数据与备份也属于秘密。

`.env.example` 只提供虚构域名与空凭据。`.gitignore` 和 `.dockerignore` 同时排除秘密。公开 CA 证书的域名/公钥不能视为秘密，仓库脱敏不等于证书透明度保密。

本地为研发环境，未经用户明确要求不启动项目容器。构建/发布脚本优先 Python；C端 `.bat`/`.sh` 是用户明确要求的产品入口例外。
