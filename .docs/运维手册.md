## 私密对象与备份

`.env`只保存在各端本地，实际域名、管理Key、证书路径和私有镜像仓库不得进入Git。`STATE_DIR`为业务投影，`AUTHORITY_DIR`是最新授权账本和加密密钥库，`SESSION_MASTER_KEY_FILE`为独立32字节主密钥。三者分开保存；备份也属于私密数据，不放构建上下文或镜像。

部署前提供独立持久目录、正确UID权限及有效LE证书目录。不要在授权文件丢失后重新initialize冒充原实例。初始化只用于全新实例：构建后的`node dist/server/index.js --initialize-authority`；读取相同私密环境，已有权威拒绝覆盖。

根目录Python入口从本地`.env`加载环境。数据库在线备份：`python backup.py --database`，使用SQLite backup API，输出位于私密state/backups。权威备份：停止本项目写者后运行`python backup.py --authority`；主密钥单独保护，不把备份视为永远最新的权威。

数据库恢复：停止本项目访问但不撤销授权，保全当前三类私密对象，运行`python restore.py --database <备份.db>`。工具验证备份manifest/实例/世代，备份当前投影，再用最新完整账本重建全部有效和已撤销状态；不把旧DB作为授权事实。权威校验：写者停止时运行`python restore.py --verify-authority <权威目录>`，只验证，不启动服务。

权威、head、密钥缺失或完整性不明必须冻结，保留原文件用于恢复。不生成新密钥尝试解密，不复制旧全量快照覆盖较新的撤销记录，不通过删除锁文件绕过正在运行的写者。停止访问、超时与冻结均不等于主动撤销。

## 发布与证书

`rebuild.py`仅构建推送，不能附带启动本地服务。真实仓库通过`.env`注入，输出必须掩码。注册表按digest清理前保护latest与当前SHA的digest，共用者跳过。本轮已完成构建推送及生产镜像内容检查。

生产仅nginx映射5116，app及SSH代理不发布公网端口。LE使用宿主acme.sh DNS-01；证书整目录只读挂载。复用共享证书时必须保留原reload链路，加入本项目nginx配置检查和reload，不覆盖其他服务的唯一hook。证书错误不能通过关闭TLS校验解决。

升级/重启必须使用相同权威、主密钥和state；先拉镜像、备份、预检，再重启并等待health。健康失败不清旧镜像、不自动全撤销、不继续公开访问。镜像回退只在schema兼容范围内执行，权威数据不随之回退。首次空目录部署使用`python3 restart.py --initialize`；普通更新用`python3 restart.py`，兼容回退用`python3 restart.py --tag <compatible-sha>`。初始化后不得再次initialize。实际容器健康、重启与崩溃恢复通过；c897d1b→50a74d5→c897d1b兼容回退与切回通过，各次HTTPS ready和会话状态一致，权威不回退。

## 撤销与日志

S端显式`session disconnect`或C端GUI断开才永久撤权；服务端先持久撤销，再切流及清活跃秘密。若C离线，S撤销生效不等于C已经清理；状态应明确pending，待C重连仅补交清理。

默认不持久化命令正文、参数内容、终端输出、文件内容与脚本。exec输出只在内存限额保存10分钟。宿主sshd、systemd journal、反向代理和运维终端可能独立记录元数据，应按各自配置管理；不要把完整请求/Authorization/Cookie/邀请码加入调试日志。

备份中的旧密钥无法承诺物理擦除，需加密、限定访问及按运维策略删除。禁止将曾经的备份直接恢复为当前权威以复活已撤销授权。测试仅清理本次专用资源，不动其他服务、账户、会话或5115现有业务。


## 宿主隔离前提

实际部署配置与持久数据位置只保存在私密环境中。其他容器若可写挂载权威目录或其上级目录，部署脚本拒绝继续；不要关闭此检查。通用部署目录被其他业务挂载时，应使用独立目录，且满足Snap Docker可访问路径。tmpfs及只读挂载不构成并发写者判断。root与Docker守护程序仍属于可信管理边界。

## A18容器运行基线

按用户明确批准，两个容器以root运行，移除no-new-privileges并设置apparmor=unconfined。app移除全部capabilities，gateway仅保留SETGID用于nginx初始化用户组；只读rootfs与私密挂载保持。TLS_KEY_UID/GID默认0，证书私钥root0600；state、authority和主密钥归root，运行tmpfs使用uid/gid0。独立私密目录不得位于其他容器已挂载目录下。

## P12 原生客户端发行

S端仍使用Node24；新C端不再打包Node。先以固定Go工具链及微软官方ZIP离线构建签名发行：

```text
python scripts/client-release.py --go <go.exe> --key <private-release.key> --openssh-dir <含固定OpenSSH-Win64.zip的目录> --output <私密发行目录>
```

脚本核对Go1.27.3、固定ZIP SHA256和逐文件微软发布者，只收六组件及许可证；manifest v2与index均离线签名。`go.mod/go.sum`固定第三方依赖，微软发布者摘要见公开元数据文件。客户端release、设备和S端会话密钥分权；所有原始包、私钥和签名产物均不入Git/镜像。维护者跟踪Preview安全更新，审核测试后重建，禁止自动升级C端系统SSH。

每次发行先提交源码，rebuild.py构建并推送；将双平台包、index.json/index.sig放在生产新的独立0700目录（文件0600），核对四文件SHA256后更新私密CLIENT_ARTIFACT_DIR与IMAGE_TAG，使用restart.py --tag <源码SHA>。保留原发行目录和镜像用于兼容回退。旧Node会话继续其原客户端，S端协议兼容，不自动迁移/撤销。实际生产SHA以最新交接014和验收记录为准。
