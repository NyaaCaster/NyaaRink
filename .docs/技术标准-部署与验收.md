# 技术标准：本地研发、macmini部署与验收

2026-10-22，已批准设计基线1，对应R01、R08。端口5116、本地研发/ macmini运行已批准；2026-10-22用户追加授权提交推送及连续实施部署。

## 1. 工程布局

推荐npm workspaces：`apps/web`（邀请页）、`apps/server`（REST/MCP/隧道/授权）、`apps/cli`、`apps/client`（C连接程序）、`packages/contracts`（schema）、`packages/version`（版本/签名）、`scripts`（Python发布与运维）、`nginx`（模板）。业务子系统代号：Clavis Astralis（邀请/授权）、Lumen Bridge（隧道）、Mnemosyne Vault（权威/恢复）；不影响清晰的路由和文件命名。

根package.json version为发行版本SSOT，构建生成版本模块，meta.json只引用项目元信息而不重复维护版本。前端HTML data-blessing、入口console日志和CLI --version至少两个运行时位置展示`Nyaa be with you.`，不能用注释替代。初始闭环目标V1，发行版本从0.1.0开始，未验收不标稳定版。

Node24 Debian slim为服务基础镜像，固定补丁/镜像digest，避免旧Node20及Alpine原生模块组合成本。SQLite WAL/foreign_keys/busy_timeout和严格schema迁移；投影DB写入前做一致备份。TypeScript strict、ESM、ES2022，npm唯一包管理，package-lock入库，npm ci。ESLint9扁平配置、Vitest核心测试、Playwright关键浏览器流程。无需为每个可逆文档改动编写镜像测试。

## 2. 容器拓扑与配置

- 两服务：nginx TLS入口、Node app；仅nginx映射`${PUBLIC_PORT:-5116}:8443`，app3000仅内部网络可达；不发布SSH端口。
- nginx与app均专用用户、drop全部capabilities、no-new-privileges、只读rootfs，必要run/tmp目录tmpfs，restart unless-stopped。app需要持久目录写权限，不挂Docker socket，不使用privileged/host网络。
- 资源默认：app内存1GiB/CPU2，nginx128MiB/CPU0.5；生产默认20会话、每会话4个SSH流。此为保护配额，不是已实测容量承诺。
- Docker nginx终止TLS，转发API/MCP与WSS，Upgrade/Connection正确处理，长连接proxy_read_timeout至少75秒，禁buffering。UI和公开包可缓存，邀请、脚本、Cookie与API不缓存。只接受配置域名，不把Host头当任意上游。
- Node校验转发来源只信任内部nginx，拒绝伪造X-Forwarded-*；管理及设备鉴权在Node再次执行，不能只靠nginx保护。

环境契约（示例只能虚构，无真实值）：

| 变量 | 用途 |
| --- | --- |
| PUBLIC_BASE_URL | `https://example.invalid:5116`，URL与端口必须一致 |
| PUBLIC_PORT | 5116，保留可配置性，禁止误用现有5115 |
| MCP_API_KEY / MCP_API_KEY_PREVIOUS | 当前管理Key及可选轮换Key |
| API_KEY_PREVIOUS_UNTIL | 可选旧Key截止UTC，最长24小时 |
| TLS_CERT_DIR | 宿主证书目录，只读挂载nginx |
| STATE_DIR | 业务DB/投影，私密持久目录 |
| AUTHORITY_DIR | 独立账本/密钥库目录，不随DB恢复覆盖 |
| SESSION_MASTER_KEY_FILE | 私密主密钥文件，app只读挂载 |
| CLIENT_ARTIFACT_DIR | 经签名的客户端发行包，只读 |
| PRIVATE_DOCKER_REGISTRY_HOST | 私有镜像仓库，仅.env注入，输出统一掩码 |

公开模板不得写真实主机地址、域名、证书目录、管理Key和私有仓库地址。启动检查缺Key、TLS挂载缺失、PUBLIC_BASE_URL非HTTPS、端口不一致、权威损坏一律拒绝ready。错误不输出秘密。

## 3. LE证书与续期

宿主acme.sh DNS-01签发覆盖PUBLIC_BASE_URL域名的LE证书，DNS凭据留宿主权限受限文件；容器仅挂整目录的fullchain与privkey，只读。证书续期使用目录挂载以处理原子替换，不单文件绑定旧inode。

发行机先核实已有证书SAN、私钥权限及续期链路。若复用现有共享证书，不覆盖其唯一install-cert或reloadcmd；合并现有宿主nginx reload与本项目nginx `nginx -t`、受控reload。若专用证书则独立签发、独立hook。此条件由实际域名/证书匹配确定，不需临时选择新架构。

无需HTTP80挑战，不为ACME开放额外公网端口；公网只暴露5116。路由器TCP映射到macmini的5116，TLS在容器nginx终止。HTTPS域名错误/过期不能通过`-k`作为生产解法。签发与续期是生产运维，需要部署阶段实际验证。

## 4. 本地至生产流程

1. Windows研发目录、私密测试数据与大文件目录分离；本机大文件使用`E:\DockerRes\NyaaRink`。未经用户要求不启动本地容器；测试先用临时目录原生进程与回环端口，正式容器集成需明确授权。
2. `rebuild.py`只build、tag、push与合规清理，不启动容器；PAT仅用于GitHub交互且不落文件，不改remote。镜像仓库值从.env读取，输出掩码。
3. Registry清理先取得latest和当前sha的digest保护集合，共享digest一律跳过，不能按过期tag直接删共用manifest。推送失败不进入部署。
4. `docker-compose.yml`本地含build，`docker-compose.publish.yml`仅引用`${PRIVATE_DOCKER_REGISTRY_HOST:?err}/nyaarink:<tag>`，默认latest并保留可指定SHA标签。生产文件传至macmini部署目录，真实.env单独传输、不进仓库。
5. macmini应用配置使用`/root/DockerContainer/NyaaRink`，业务、权威、备份与主密钥分别放私密持久目录；私密路径由.env填写，不复制现有证书路径进入源码。Snap Docker调用补充`/snap/bin` PATH。
6. `restart.py`先pull、备份和预检，再停本项目、快照私密数据、离线预检、up及等待health；保留上一兼容标签用于回退，不全局prune；不得全局删除无关容器/数据。日志只有掩码信息。
7. 无旧NyaaRink实例则首次安装；若已有本地对外源实例，按工作空间迁移规则先停止源写入再迁移，不影响其他项目。当前没有本项目运行实例。

端口5116在部署前再次检测；若被占用则失败并报告，不抢占其他服务、不自动顺延，变更PUBLIC_BASE_URL必须经用户确认。当前5115已有服务保持原状。

## 5. 更新、失败和回退

普通应用更新保留所有授权、账本、密钥库和设备凭据。进入维护状态只暂停访问，不撤销。迁移前备份DB，权威格式需向后读取兼容；禁止用旧镜像强读新schema。镜像回退只能在声明兼容的范围内执行，数据不可随镜像回退覆盖权威记录。

健康失败不继续公开访问，不自动全撤销。回退到兼容上一镜像仍使用当前权威目录；若没有兼容镜像则冻结等待修复。C继续退避重连，原生SSH配置仅在授权有效且权威可用时生成。LE更新不重置业务授权。
