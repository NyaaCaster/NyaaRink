# 技术标准：授权生命周期与隧道

版本：已批准设计基线 1，2026-10-22。对应已批准 R04–R06、R08；业务硬约束已批准。所有时间使用 UTC存储、前端本地化展示，时长基于单调时钟与服务端事件计算。

## 1. 状态模型

- invitation：`issued → consumed`，或未接受时 `expired/cancelled`。GET不迁移状态。默认24小时有效。取消未接受邀请与撤销已授权会话是不同操作。
- authorization：`accepted → enrolled → revoked`。accepted即接受授权、消费邀请，enrolled表示设备已绑定。没有网络超时触发的撤销迁移。冻结为可访问性标志，不改授权状态。
- connectivity：`waiting / online / offline / reconnecting`，完全独立于authorization。
- cleanup：`not_needed / pending / confirmed / failed`，撤销不等待清理成功。failed可以重试。
- execution：`queued / running / succeeded / failed / cancelled / interrupted`，执行超时仅影响任务。

`revoked`不可逆。暂停访问、停止服务、注销、退出SSH、删除浏览器Cookie、升级、进程崩溃都不能代替主动撤销。C用户主动卸载/本地结束入口要明确显示其同时执行本次断开并要求确认。

## 2. 邀请接受与登记

1. S创建邀请：生成32字节CSPRNG随机值、base64url无填充编码；服务只存其SHA-256摘要，完整URL仅创建时返回。随机后缀为顶级路径，保留 `/api /mcp /assets /downloads /recover /healthz` 等固定路由。
2. 浏览器GET邀请显示身份、用途、范围、日志、AI与自动恢复告知，建立独立浏览器nonce；GET不消耗邀请。所有邀请及会话响应 `Cache-Control: no-store`、`Referrer-Policy: no-referrer`。
3. C点击接受：POST必须具有准确Origin、浏览器nonce、CSRF及幂等ID。锁定邀请码，先向权威账本提交“邀请消费+授权+浏览器绑定”一个事件，fsync成功才返回；SQLite投影失败必须由账本恢复，不能再次接受。
4. 同一浏览器同一幂等ID重试得到同一结果；其他浏览器再访问原链接得到统一无效页，不泄漏目标账户/在线状态。原浏览器Cookie可刷新恢复有效会话。
5. 接受后可下载本次bat/sh：含256位引导Key、sessionId、登记ID、固定HTTPS来源与版本。10分钟一次兑换，HTTPS响应及日志不得缓存/记录其内容。原浏览器在尚未登记设备时可重发脚本，立即废止前一引导Key；已登记不允许另绑设备。
6. C程序先生成本地Ed25519设备密钥并安全落盘，打印实际OS账户、权限和远端来源，用户本地确认；收集并验证本机sshd公钥，提交设备公钥+账户+主机身份。引导Key原子绑定此设备，登记响应允许相同登记ID和同设备签名幂等重取；不允许仅持旧引导Key替换设备身份。
7. S生成每会话独立Ed25519 SSH密钥，公钥给C，私钥留S。C仅添加带session唯一标记的授权行；安装、主机核验、自启动均成功后报告ready。部分失败由补偿状态机重试或用户主动撤销，不偷改成“已上线”。
8. 目标账户为本地确认的实际账户；浏览器接受时告知“稍后在本机确认账户”，不能提前伪称已授权某管理员。S传来的账户字符串不能覆盖C本地确认。

## 3. 浏览器身份与恢复

使用 `__Host-nr` Secure、HttpOnly、SameSite=Strict、Path=/ Cookie；服务端仅存摘要，持久化浏览器绑定并加密保存必要恢复材料，浏览器本地默认不保存管理/设备密钥。Cookie期限可续，过期只失去页面访问身份，不撤销SSH。

`/recover`为无私密信息的通用恢复页，产生12字符随机base32配对码，5分钟有效。用户在C程序执行 `resume-browser <code>`，本机再次确认并以设备签名认领浏览器挑战。码只配对浏览器，不可绑定新设备或获S管理权；每IP每分钟5次、每挑战最多5次，成功一次失效。设备丢失时必须另行主动结束旧授权后新建邀请。

断开成功当前页面保留结束结果与“删除下载脚本”提示；后续刷新返回无效页面。未收到成功响应不能宣称撤销完成，应显示待核实并允许幂等重试。原授权Cookie不因浏览器关闭自动结束会话。

## 4. WSS通道协议 v1

- `/api/v1/device/control`：一个设备只保持一条控制WSS。TLS后采用服务随机nonce，C对 `protocolVersion | instanceId | epoch | sessionId | nonce | devicePublicKey` 签名。nonce单用、30秒有效；证书、设备公钥、实例世代和会话状态同时核验。
- 控制JSON envelope：`{v:1,type,id,epoch,sessionId,generation,payload}`；严格schema、未知type拒绝。固定消息：hello/challenge/auth/ready、open/ready/error、status、revoke/cleanup_ack、ping/pong。不得携带任意TCP目标。
- 每次控制连接成功，S原子分配递增generation，关闭旧generation全部数据流。重连不透明恢复旧SSH字节流；旧交互任务标记interrupted，不重放命令。
- S要建立SSH时发送open，含streamId及256位一次性ticket。C向 `/api/v1/device/streams/{streamId}` 主动发起独立WSS，Authorization头带ticket；30秒有效，绑定设备/session/generation/用途，原子消费。ticket不放URL或子协议。
- C本地只连接登记的 `127.0.0.1` 或 `::1` 的sshd端口。地址必须为回环字面量，不解析远端提供域名。S不传任意目标。数据WSS只传原始SSH二进制流，S用ssh2 `sock`或本地OpenSSH ProxyCommand连接。
- 数据流以`ws.createWebSocketStream`连接Node Duplex，使用pipe背压；每message最大256KiB，写入分块64KiB，默认highWaterMark64KiB。关闭压缩，每流待发队列上限1MiB，超过则中断该流，不撤销授权。半关闭按SSH的EOF/channel语义处理；不承诺WSS物理连接支持TCP半关闭。
- 控制消息最大32KiB；心跳15秒、连续45秒无回应判离线，重连指数退避1–30秒并加抖动。任何心跳超时不触发revoked。
- 默认20个非撤销会话、每会话4条SSH流；单会话10MiB/s双向合计令牌桶、排队开流最长30秒、全局128MiB应用排队预算。达到限额返回可重试错误，不撤销。
- 不允许跨主机自动跳转，不允许TLS验证关闭。Host/Origin白名单来自PUBLIC_BASE_URL；无Origin的设备/CLI仍须完整鉴权。

## 5. 主动断开时序

S管理API、MCP、CLI与C网页统一调用幂等revoke业务函数，记录actor=`s_operator/c_browser/c_local`，原因及requestId。

1. 在全局授权写锁内校验会话，将不可逆revoked事件追加并fsync；这一时刻为撤销生效点。
2. 撤销浏览器操作能力、设备访问权、引导Key、所有未用ticket；再开流必须核验权威状态，不能仅看缓存。
3. 终止此会话全部SSH channel、SSH连接、WSS数据流、本地ProxyCommand连接和执行任务，移除S临时配置、已解密私钥及活跃密钥文件。
4. 控制连接仅允许发送revoke与接收cleanup_ack，之后关闭。C离线时标记pending；重新认证不授访问，只允许签名撤销查询与清理回执，保留设备公钥摘要/验证材料而非活跃访问凭据。
5. C只删除本次公钥行、会话设备私钥、运行文件、自启动项；写入本地撤销标记后再清理。共享运行时无其他会话引用才清理。删除失败保留failed并提示具体路径，不报全部完成。
6. 响应分别给出 `authorization=revoked`、`accessClosed`、`sCleanup`、`cCleanup`。通常5秒内终止在线流；超时返回真实pending，不回滚revoked。

C本地紧急撤销无须S在线：先fsync本地撤销标记，阻断新流并关闭本地套接字、移除公钥/登录项，再在网络恢复后签名补交撤销。补交前只保留用于证明本次撤销的设备凭据，禁止以其恢复访问；收到S回执后销毁。网页不能访问本地文件或可靠代替这一入口，应提供明确命令和步骤。

## 6. 指标定义

- `authorizedSeconds`：accepted至当前/撤销，含离线时间；`onlineSeconds`：控制通道认证online区间累计，重启由事件重建，崩溃间隙不能虚构精确在线秒数。
- `sshConnectionsOpened`：成功通过SSH认证的连接总数；`sshConnectionsActive`：当前连接数。
- `sshBytesSToC/sshBytesCToS`：S观察到的数据WSS中的SSH字节，不含TLS开销；未完整落盘的崩溃末段允许损失最多10秒统计，并在文档标注。
- `apiOperations`：受控exec/shell/file业务调用成功受理次数，不是shell命令条数。
- `rttMs`：S发起控制ping到C应用pong的往返，展示样本时间，离线显示不可用。不是浏览器延迟，也不是每条SSH命令延迟。
- 不展示无法可靠计量的“SSH命令总数”；若显示frame计数，必须命名“WSS消息数”。
