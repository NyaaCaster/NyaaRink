# P9 Windows ACL 修复计划

2026-10-22，依据用户反馈的实际连接脚本失败，沿用连续修复、验证及发布授权。当前工具不提供模式切换，本计划落盘后实施，不声称已进入 Plan 模式。

## 问题与范围

Windows 引导和私密状态的 SetSecurityDescriptorSddlForm 单参数重载会修改包括审计在内的全部区域，触发 SeSecurityPrivilege。只设置 DACL，不要求新增系统特权或将连接程序提升运行。保留原用户、SYSTEM 限制、关闭继承、保留现有授权文件及显式断开语义。

## 实施与验证

1. 引导脚本及客户端 privatePath 显式限定 AccessControlSections.Access；检查已有授权文件 ACL 复制是否受同类问题影响。
2. Windows 真实文件/目录及生成引导脚本前缀回归：在不持有 SeSecurityPrivilege 的进程下执行，验证 DACL 白名单、继承保护、owner 和现有文件 ACL 保留；不触碰真实 sshd 或授权文件。
3. 运行客户端及全量既有验证、类型检查、lint、build，清理本轮临时数据；原 A17 未测范围继续保留。
4. 更新客户端技术标准、SSOT、验收及交接；secret/diff/status 检查后提交推送。
5. 重新制作签名客户端发行包、构建并发布镜像，macmini restart 流程备份后部署；只读检查 TLS、健康和生成脚本，保留现有授权，不创建额外邀请。

## 用户恢复方式

部署后原接受页面重新下载连接脚本再运行。引导 Key 已过期时使用同一页面补发；不主动撤销原会话，不因本次安装错误自动销毁授权。
